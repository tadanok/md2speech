# md2speech

Markdown ファイルを [Google Cloud Text-to-Speech](https://cloud.google.com/text-to-speech) API で日本語音声(MP3)に変換する CLI スクリプトです。

## 特徴

- Markdown の見出し・太字・インラインコード・箇条書き・リンク・裸URLなどを読み上げ用に自動整形
- `## ` 見出し(章)単位でテキストを分割したうえで、API の1リクエストあたりの上限バイト数を考慮して自動でチャンク分割(章をまたいでチャンクを結合しない)
  - 最初の `## ` より前にあるタイトルや前書きは「はじめに」として保持
  - フェンスコードブロック内の `## ` は章見出しとして扱わない
- チャンクの本文と音声設定から作ったハッシュで中間音声をキャッシュするため、途中でエラーが発生しても再実行時に続きから再開可能
- 生成した音声パートを結合して1つの MP3 ファイルを出力し、各パートの実測再生時間から章の開始/終了時刻を算出してID3チャプターマーカー(CHAP/CTOC)を埋め込む
  - 対応プレイヤー(Podcastアプリ、iTunes/Music、Audible系アプリなど)で章単位のジャンプが可能になる
- 章ごとの個別 MP3 ファイルも入力ごとの章ディレクトリに `01_章タイトル.mp3` の形式で出力(ID3非対応の環境でもファイル単位で章を選べる)
- 完成版は一時ファイルとして作成してから置き換えるため、処理途中の失敗で以前の完成版を壊さない

## 必要なもの

- Python 3.7 以上
- [mutagen](https://mutagen.readthedocs.io/)(ID3チャプターの埋め込みに使用)

  ```bash
  pip install -r requirements.txt
  ```

- Google Cloud Text-to-Speech の API キー

## セットアップ

1. [Google Cloud Console](https://console.cloud.google.com/) で Text-to-Speech API を有効化し、APIキーを発行します。
2. 依存パッケージをインストールします。

   ```bash
   pip install -r requirements.txt
   ```

3. 環境変数にAPIキーを設定します。

   ```bash
   export GOOGLE_TTS_API_KEY="あなたのAPIキー"
   ```

## 使い方

```bash
python3 md2speech.py 入力ファイル.md
```

例えば `/path/to/book.md` を実行すると、入力ファイルと同じディレクトリに以下が生成されます。

- `/path/to/book.mp3`: 全体を結合し、ID3チャプターマーカーを埋め込んだ完成版
- `/path/to/book_chapters/01_章タイトル.mp3`, ...: 章ごとの個別ファイル
- `/path/to/.md2speech-cache/book-<識別子>/parts/<ハッシュ>.mp3`: 再実行時に利用する中間音声

完成版の名前はMarkdownのH1ではなく、入力ファイル名を基準に決まります。どのディレクトリからコマンドを実行しても、出力先は入力ファイルと同じディレクトリです。

生成後は以下で再生できます(macOS の場合)。

```bash
afplay /path/to/book.mp3
```

## 設定のカスタマイズ

`md2speech.py` 冒頭の定数を編集することで、音声の設定を変更できます。

| 定数 | 説明 | デフォルト |
| --- | --- | --- |
| `VOICE` | 言語・話者(音声モデル) | `ja-JP` / `ja-JP-Neural2-B` |
| `AUDIO_CONFIG` | 音声形式・話速など | MP3 / 標準速度(`1.0`) |
| `MAX_BYTES` | 1リクエストあたりの最大バイト数 | `4500` |

利用可能な音声の一覧は [Text-to-Speech の音声リスト](https://cloud.google.com/text-to-speech/docs/voices) を参照してください。

## 章の分割について

入力Markdown内の `## ` 見出し(レベル2)を章の区切りとして扱います。`### ` 以下の見出しは章とは見なされず、本文として読み上げられます。最初の `## ` より前に読み上げる内容があれば、「はじめに」という章になります。フェンスコードブロック内の `## ` は章の区切りになりません。

見出しが1つも無いファイルを渡した場合は、全体を1つのセクションとして扱い、チャプターマーカーの埋め込みと章別出力は行いません。Markdown整形後に読み上げる内容が残らない場合は、空のMP3を生成せずに終了します。

章ディレクトリ内のファイル名は見出しテキストを使用しますが、ファイル名に使えない文字(`\ / : * ? " < > |`)は `_` に置換されます。

## キャッシュと再実行

中間音声は入力ファイルごとに分離した `.md2speech-cache/` 以下へ保存されます。キャッシュキーには本文だけでなく、`VOICE`、`AUDIO_CONFIG`、キャッシュ形式のバージョンも含まれます。

- 本文と音声設定が同じチャンクは再利用され、APIを再度呼び出しません。
- 話者や話速を変更すると、新しい音声として自動的に生成されます。
- APIエラーなどで途中終了しても、生成済みチャンクは次回利用されます。
- 実行開始時にキャッシュや章ディレクトリを一括削除することはありません。
- 古い章ファイルを整理するときも、マニフェストに記録された、このツールが生成したファイルだけを削除します。

旧バージョンが作成した `tts_parts/` と `chapters/` は自動削除されません。不要であることを確認したうえで、手動で整理してください。

## テスト

Google Cloud APIを呼ばずに、章分割、キャッシュ、出力先、空入力などを確認できます。

```bash
python3 -m unittest discover -s tests -v
```

## 注意事項

- Google Cloud Text-to-Speech API は利用量に応じて課金されます。事前に[料金体系](https://cloud.google.com/text-to-speech/pricing)をご確認ください。
- 完成版や今回更新する章ファイルが既に存在する場合、API呼び出しを行う前に上書きしてよいか確認を求められます。`y` 以外を入力すると、既存ファイルを変更せずに中断します。
- キャッシュは自動では削除されないため、長期間利用すると `.md2speech-cache/` の容量が増えることがあります。
